〇、一句话电梯稿

这是一个 7×24 小时替客户盯着全网热点、自动完成研判、最后交出带证据链报告 的舆情 Agent 系统。 热点它自己发现、子问题它自己拆解和调查、每个结论强制挂证据、质疑环节机器先互搏一轮， 人只做两件事：在关键闸门上审批，和随时插话问进展。市面上的监测系统止步于"告诉你有热点"， 我们的系统回答"该不该管、怎么管、证据在哪"。

布局三级：左侧业务入口（仪表盘/对话/议题/信号/研判链路/信源/采集流水/报告中心/品牌监测）＋ 右上角上下文按钮（🧩 团队 → 右侧抽屉）＋ 定制中心（系统配置收纳，chips 过滤）。页面保持扫一眼的密度，深挖内容一律"点了才从右边伸出面板"。

三、给客户的 5 步演示脚本（15 分钟版）

仪表盘——先证明它活着

指五张 KPI 卡和活动流滚动：值守 Agent 刚在 12 分钟前自动并入了一条命中。

"这是系统此刻的全局状态——它不是等您来查，它一直在自己干活。"
议题——给事件立个案

打开闲鱼议题：生命周期三态、子题进度 4/5、热度时间线上 9/21 爆发日一眼可见。

"热搜爆了它自己发现、自己立案、自己拆解——您零操作。"
研判链路——摊开 AI 怎么想的

从起点讲到信号节点：谁首发、几点引爆、官方回应、哪个结论被质疑者打回过。

"别的系统给您一个结论，我们给您结论的推导过程——这里有个节点标着'存疑'，是我们自己的质疑 Agent 打回去的。"
信号+对话——插一句话看它转向

点开一条高危信号看证据引用；回对话页现场输入"重点查首发信源"，看规划者现场派工。

"您随时可以插话，它按您的优先级重排调查——这是人在环路，不是黑盒跑批。"
审批+报告——闸门和交付

审批页那条"登录态深挖待审批"：系统想要、守则拦住、等人点头。报告中心点开事件报告卡片，右侧面板直接预览：数据洞察层代码出图、专题层引用挂链。

"它能干的事都有边界，出的每句话都有出处——这您才敢往上递。"
（加分项）品牌监测+团队——从监测到决策的完整闭环

品牌监测页：本品+竞品阵营、负面率对比给出"转化窗口"结论；每日竞品简报一键生成周报。回对话页右上角「团队」：组队草案确认后看板亮起，Agent 网络里每个成员的 token 成本一目了然。

"监测只是起点，带证据的决策建议才是交付——而且每个 Agent 花了多少成本，账单透明。"

四、四个卖点（对着不同客户换顺序）

⛓ 证据链强制

结论必须挂原文链接+抓取时间，核不过就标存疑。对应客户痛点：AI 报告不敢往上报。

⚔ 机器自查先于人查

质疑 Agent 专挑自家结论的刺：单源打回、口径复核。舆情翻车最怕"一面之词"。

🛡 合规闸门内建

采集守则+审批+PII 脱敏+全审计日志。对应客户痛点：采购舆情系统最怕数据来源出事。

📜 过程全可视

研判链路把 AI 推理摊开给人看。对应客户痛点：黑盒系统出了错都不知道错哪。

五、客户常问三题（备答）

Q1 数据覆盖多少平台？ 答：热榜层 8+ 平台分钟级，检索层联网全量，深挖层（评论区等登录态数据）走审批制按需采集——我们按研判需要取数，不吹"全网全量"，吹的是取的都是有用的。

Q2 跟 XX 监测系统比差异？ 答：监测系统到"预警"为止，我们从预警往后走完"研判-质疑-报告"；且每条结论可回溯，不是模型张口就来。

Q3 AI 说错了谁负责？ 答：三层兜底——核实员核证据、质疑者挑毛病、关键动作和成稿必须人工审批。系统设计目标就是把"AI 错"拦截在"人签字"之前。
