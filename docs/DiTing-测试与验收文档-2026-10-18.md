### C01：实际 dsh 的挂起请求取消

命令：`npm run runtime:check -- --cancel`。

1. 创建隔离任务和配置，模型服务器仅监听 loopback，使用明确无效的测试凭据与测试费率。
2. 真实 dsh 启动领域 profile 并请求测试模型；服务器收到请求后刻意不返回。
3. 将任务置为 cancelled，关闭该任务的 dsh 执行，等待 launch 结束。
4. 检查任务仍为 cancelled，报告/证据/业务产物均未新增；模拟迟到结束不能改写状态，旧租约归档被拒绝。

本轮实际观察到一条挂起的 root 模型请求、0 份报告、0 份证据。没有请求外部模型。这个场景没有创建调查子 Agent；子 Agent 已启动后不同阶段的实际取消仍需扩大演练。

## 7. 首份真实报告的验收方案

### 执行前准备

- 在 LLM 模型与路由填写实际研究模型的输入、缓存、输出费率及合适的输出上限；确认研究执行配置。未知费率不能伪装成免费。
- 使用已经实际验证可用的搜索服务；先用公开可访问原文完成新闻研究。平台登录条件未满足时，明确将评论研究列为未覆盖，不能因此阻断所有公开资料研究。
- 如要验收平台正文/评论，在本机配置自己的 Cookie，不在对话、文档或仓库中粘贴凭据。先单独验证，再批准最小采样范围。

### 固定验收主题

对话输入示例：

> 调查近7天 AI 行业的主要争议，区分公开事实、各方观点与未证实说法。预算上限30元，输出完整报告、可复算表格和来源附录；无法取得的平台评论请明确说明。

验收时记录任务 ID、模型版本、配置快照、研究时间窗、开始/结束时间、每个成员的实际产物和缺口。只有实际执行，才填写耗时和费用；不能承诺尚未测量的 30–60 分钟目标。

### 报告必须逐项检查

1. 研究对象、日期窗口、样本取得方式、样本量与局限是否清楚；平台样本不代表总体公众观点。
2. 主要事实结论能否定位到归档原文及原句；检索摘要不能替代原文证据；转载不能直接算作独立交叉验证。
3. Insight/Media/Query 是否有独立成果和覆盖说明；Forum 是否记录实质分歧，门禁是否审查当前证据版本；不足时是否补证或降级结论。
4. 数字能否从引用或代码底表复算；情感标签是否有原文依据，未标注不当中性，发布时间不使用抓取时间替代。
5. 按用户提供的 PDF 和完整报告标准检查章节、分析深度、表格、图表、附录与阅读体验。页数、引用数量不能单独代表质量；缺乏材料不得硬凑篇幅。
6. HTML、Markdown、PDF 的内容和统计是否一致；PDF 有无截断、乱码、空白页和图表不可读。
7. 报告追问是否使用该固定版本及证据；补充研究是否保留旧报告并生成独立新版本。

验收结果分为“通过”“受限交付”“失败”：范围内关键要求满足才通过；明确披露采集不足、只能支持较窄结论时记录受限交付；伪造来源、数字无法追溯、越权采集、门禁绕过均不能通过。
