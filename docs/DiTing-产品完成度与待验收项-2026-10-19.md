## 仍需完成与验收的工作

### 需要外部条件

1. **社交平台真采样**：由用户在本地保存微博/B站登录态，批准最小采集范围；核对正文、评论、作者、发布时间和可见互动字段。无权访问时报告明确写受限，不把空结果当零声量。
2. **指定通知通道验收**：配置用户选择的飞书/企业微信目标与凭据，使用测试事件检查消息、报告链接、失败重试、去重和撤销订阅。
3. **真实值守验收**：启用少量监测规则和预算上限，观察新快照触发、重复信号抑制、自动开题与人工研究排队；至少跨夜运行并保留日志与决策记录。
4. **成本基线**：在预算内完成 2–3 个范围可控的真实主题，逐角色记录调用、输入/输出/缓存 Token、费用、证据增量、耗时、报告实质字数与人工抽检。已有 537 次/约 19.85 元案例只说明成本曾逼近上限，不能外推为常规价格。
5. **CI 外部执行**：配置仓库 remote 并推送后，检查 GitHub Actions 首次运行。当前没有 remote，所以不能报告云端 CI 已通过。

### 仍属实现/验证差距

- 实体、地域、传播互动统计与跨来源事件聚类未完整实现；现有样本图表只对实际归档网页计数。
- Verifier 的自然语言事实蕴含仍不能被纯结构规则完全保证；数字主体错配、门禁版本等已覆盖部分边界，仍须人工抽检。
- 报告追问、模板共创、历史相似、品牌监测及完整可执行自定义 Tool 尚须按产品约定逐项验收或列为后续版本。
- 52 个规划热榜源未全部完成逐源实测。接口受限、登录要求、字段缺失要作为源状态展示，不能用已收录目录等同接入成功。
- 真实 MCP 与外发通知未在实际目标端验收。代码可以连接不代表用户配置已完成。

## 复核结论

当前状态是“核心架构和主要页面可运行，真实热榜与一份真实研究链路有记录；报告呈现已针对已发现问题修复；多项对外业务能力仍需用户凭据或真实运行条件验收”。不能称为全部功能已完整验收的生产产品。最短验收路径是：先拿到可用社交会话并完成一份明确范围的深度任务；然后在预算约束下跑 2–3 个样本建立成本基线；再启用单条值守规则和指定通知目标做跨夜验证；最后触发云端 CI。
