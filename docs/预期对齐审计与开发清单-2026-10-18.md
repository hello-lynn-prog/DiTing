# DiTing：前期约定对齐审计与开发清单

日期：2026-10-18。依据：本会话最新产品约定、`DiTing-整体实施规划-v6-2026-10-18.md`、v5 zip/解压原型、完整报告验收文档及当前实际代码。

**结论：尚未完全一一对齐，不能把当前版本称为完整成品。** 页面入口、后端实现、合成测试、实际供应商调用、真实报告质量分别核对。历史文档里的“已完成”多数是原型交互或合成流程通过，不能合并成真实业务已验收。

最新进一步核对见 [目标差距复核](DiTing-目标差距复核-2026-10-18.md)。已用隔离合成探测确认：数值归属错配可通过当前数字出现校验、专属模板章节未强制、没有标题的上传模板可保存；另外长文成稿仍要求再次回传全文。这些是尚需开发的边界，不能仅归因于缺费率或真实验收。

## 三、真实执行条件与剩余顺序

1. 取得研究模型准确的输入/缓存/输出费率，保留未知费用；为实际研究槽设置合适输出上限，开启执行开关后再开始固定主题验收。已在本会话询问费率，不能默认免费或用虚构单价绕过预算。
2. 在已可用的 Tavily + 内部原文抓取上跑真实主题，逐项检查来源、原文、三成员成果、Forum 轮次、三审、章节、底表、PDF 和报告追问。首次失败也必须保留失败证据，修复后重测。
3. 完成平台级关键词与评论采集模块，记录真实发布时间/主体/互动字段、分页、登录条件、截断与失败；据此增加真正的时间线和样本分布统计。
4. 完成多模态、MCP/Skill 的真实业务联验、暗语词库及真实标注抽检；按固定案例评测，而非只增加配置卡片。
5. 最后做计划跨天、重启/断网、运行中取消、通知去重与真实群投递的验收。全部关键验收通过后，才进入之前约定的仓库推送步骤。

## 四、本轮已取得的证据

- `npm test`：38 项通过，包含首次刷新同步、原版 27 频道、独立采集计划、任务真实成员与消费数据、统计缺失值和模板选择，以及关键词元数据/评论的有界归档、时间字段、去重与暂停保护。
- `npm run build`：通过。
- `npm run runtime:check -- --full`：真实 dsh 创建 8 个子会话，使用明确合成模型与材料验证三调查成员、主持、三审及 Report 分阶段成稿；HTML/MD/PDF 生成。该结果不属于真实舆情报告认证。
- `npm run runtime:check -- --fail-closed`：故意让领域插件初始化失败，验证在首次模型请求之前停止，实际模型调用数为 0。
- `npm run runtime:check -- --followup`：真实 dsh 复用同一 Insight 子会话完成第二轮提交，成员轮次状态实际更新，调查产物保留两份。
- `docs/hotlist-live-verification-2026-10-18.json`：40 个原始平台入口的最新实采结果，每源保留条数、指标条数、时间和错误。
- `docs/search-live-verification-2026-10-18.json`：真实搜索供应商协议验证；Tavily 8 个链接，Bocha 403。
- `docs/keyword-live-verification-2026-10-18.json`：B 站原生关键词模块本轮请求 412，未取得样本、未生成报告。不得把模块回归测试的合成评论当作真实采集。
- 本轮未推送仓库，未将凭据文件或明文密钥写入源码、文档和页面；只把用户已授权、实际验证通过的 Tavily 凭据加密保存到后端。未向真实飞书/企业微信群发送测试消息。

## 五、继续开发：原生 Skill 与对话分流

本次新增 `packages/domain/skills.ts` 和 `web/skill-controls.js`，前端仍使用 v5 原布局与彩色卡片。十项技能中八项是本项目独立编写、与现有工具配套的指令；暗语库、历史相似检索缺少业务实现和评测，继续停用。不能把八条工作指令当作八种新业务实现。

- 定制中心支持查看/编辑正文、导入 Markdown、新建、停用和按角色授权。配置保存不会显示为实际已挂载。
- 任务首次执行冻结启用技能的正文、角色和内容版本；重启后沿用冻结版本。dsh 官方 `skills` 服务、官方 `skill` 工具和会话目录负责实际注册、加载及模型上下文。
- 使用 dsh 的 Agent scope 隔离目录，不扫描用户其他技能目录。原有角色工具白名单、任务租约、取消和预算仍生效。Skill 无法赋予 shell、文件读取或外部通知权限。
- `skills.frozen`、`skill.mounted`、`skill.loaded/failed/denied` 分别记录任务版本、成员挂载、实际读取和权限拒绝。正式库没有实际运行时，页面保持空记录，不拷入测试审计。

## 六、继续开发：dsh 原生 MCP 挂载

- 新增 `packages/domain/mcp.ts`、`web/mcp-controls.js`。配置页支持 Streamable HTTP、stdio 程序与参数、精确工具名及角色授权、超时/每任务调用上限。保存不会立即运行程序。
- headers/env 私密配置加密保存、不回传浏览器；任务冻结凭据引用。轮换后保留旧引用供已启动任务继续使用；生成的 profile 只存引用以外的配置，实际凭据由隔离子进程环境提供。
- 实际连接和工具 schema 转换由 dsh 官方 `mcp-client` 完成，不是 DiTing 自行模拟 MCP 协议。连接、目录同步、授权工具存在性检查全部成功后才发出领域 profile ready。
- MCP 工具仅对授权角色可见并可调用，不能绕过任务租约、暂停、取消或预算；每服务限制任务调用次数。记录真实挂载、启动、结果/拒绝和结果哈希，供应商费用未回传保持未知。

- `runtime:check -- --mcp` 与 `--mcp-stdio`：使用明确合成本机 MCP 服务器；主 Agent 越权调用未触达服务器，Insight 授权调用成功，第二次超限被拦截；实际服务器只收到一次工具请求，返回值进入子 Agent 模型上下文。stdio 额外验证专用 env 可用、模型密钥与 MCP 私密容器未传入子进程、生成 profile 不含测试凭据。
- `runtime:check -- --mcp-fail`：授权工具不存在，领域插件启动失败，首次模型请求前停止，模型调用为零。
- 尚未挂载用户真实业务 MCP 服务，未向飞书/企微发消息；合成测试审计只存在 tmp 隔离库。MCP 页面目前正式库没有服务配置时如实显示空状态。

## 八、继续开发：登录态加密配置与原生 Media 版本审批

新增 `packages/domain/platform-accounts.ts` 和 `web/platform-account-controls.js`，未复制 Python 登录程序，也未添加外部爬虫服务。登录态属于平台采集配置，入口放在现有“定制中心 → Key 与服务”；信源、采集流水主导航保留，原版仪表盘和彩色卡片继续使用。

- 微博与 B 站分别保存用户自己提供的 Cookie，请求头格式、必需字段和有效期由后端校验。Cookie 加密、只写不回显，不写浏览器存储、任务正文、dsh profile 或模型上下文。独立“验证登录态”按钮仅请求固定只读接口，不执行搜索或评论采集。
- “保存”“平台明确已登录”“平台明确未登录”“访问受限，无法判定”分开显示。HTTP 403/412/429/432 不直接判为 Cookie 无效；保存不自动联网验证，验证登录成功也不冒充关键词采集成功。

- 原始 JSON 如包含已知 Cookie 值，在归档前脱敏；模型、证据、错误日志和下载不得回传它们。哈希对应实际归档的脱敏版本。布尔/数字字段保持原有类型，未发生脱敏的响应保留实际原始文本。
